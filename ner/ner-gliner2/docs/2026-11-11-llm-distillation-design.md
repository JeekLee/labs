# LLM 증류 실험 설계 (experiments/03)

## 목적

사람이 단 정답(KLUE-NER) 대신 **LLM이 단 정답**으로 GLiNER2 LoRA 어댑터를 학습해도 비슷한 품질이 나오는지, 그때 드는 자원(라벨링 비용·시간, 학습 시간, 추론 비용)은 얼마인지 측정한다. 증류 전후를 비교하는 예시 문장도 함께 보여준다.

배경: `notebooks/02`에서 KLUE 2,000문장(사람 정답)으로 학습한 LoRA 어댑터가 KLUE 검증 5,000문장에서 F1 0.580 → 0.812를 냈다. 사람 정답을 구하기 어려운 도메인에서는 LLM이 정답을 대신 다는 방식(증류, pseudo-label 학습)이 현실적인 대안이므로, 같은 조건에서 두 방식을 비교한다.

## 사용자가 정한 것

- **선생님 LLM**: `gpt-5.4-mini` (기존 `LLMExtractor`의 비교 기준과 동일). Claude API는 쓰지 않는다.
- **학습 문장**: KLUE 어댑터와 **같은 KLUE train 2,000문장**(seed 42 표본)을 쓴다. 사람 정답은 버리고 선생님 LLM이 정답을 새로 단다. 문장은 같고 정답 출처만 다르므로, 점수 차이는 정답(라벨) 효과로 해석할 수 있다. (처음에는 Claude가 문장을 만드는 안이었으나, 문장 효과와 라벨 효과가 섞이므로 사용자가 이 방식으로 바꿨다.)
- **레이블**: KLUE와 같은 3개, `person`(PS), `organization`(OG), `location`(LC). 날짜·시간·수량, EVENT/OBJECT, 관계는 다루지 않는다.
- **도메인**: 일상 대화로 확장하지 않는다. KLUE(뉴스·영화 리뷰) 범위에서만 실험한다.
- 증류 전후 비교 예시를 포함한다.
- 어댑터는 KLUE와 마찬가지로 LoRA로 학습한다.

## 목표 / 비목표 / 실패 조건

- 목표: 같은 시험지(KLUE 검증 5,000문장, 사람 정답)에서 네 조건을 비교하는 표, 대표 문장의 정성 비교, 자원·비용 표.
- 비목표: 대화 도메인 일반화, 관계 추출, 하이퍼파라미터 탐색, 여러 seed 반복, 통계적 유의성 검정.
- 실패 조건(동작해도 의미 없는 경우):
  - 선생님 라벨과 KLUE 표기 규칙의 차이 때문에 증류 어댑터가 부당하게 낮게 평가되고, 그 원인을 구분하지 못하는 경우.
  - 비용·시간을 실제 측정이 아닌 추정으로만 적는 경우.

## 비교 조건

| 조건 | 학습 데이터 | 상태 |
|---|---|---|
| 기본 | 없음 (multi + Kiwi) | F1 0.580, 이미 측정 |
| KLUE 어댑터 | KLUE train 2,000문장 + 사람 정답 (`outputs/klue_ner_lora/final`) | F1 0.812, 이미 측정 |
| **증류 어댑터** | 같은 KLUE train 2,000문장 + gpt-5.4-mini 정답 | 새로 학습 |
| gpt-5.4-mini | 없음 (선생님 자체) | 학습 2,000문장에서 사람 정답과의 일치도로 측정(상한선 대용). 검증 데이터에서는 호출하지 않음 |

공정 비교를 위해 증류 어댑터는 KLUE 어댑터와 같은 설정으로 학습한다: 체크포인트 `fastino/gliner2.5-multi-v1`, Kiwi 분할기, LoRA(`TrainingConfig(use_lora=True, save_adapter_only=True)`, 나머지 기본값), 2 epoch, 배치 8, seed 42, 학습 문장 수 2,000. 평가 함수는 `notebooks/02`의 `evaluate()`(범위+타입 정확 일치, 레이블별·전체 P/R/F1, 조사 포함 예측 수)를 그대로 쓴다.

## 데이터

### 학습 문장

`notebooks/02`의 표본 추출을 그대로 재현한다(`random.seed(42)` 후 `random.sample(train_rows, 2000)`). 이 2,000문장의 원문만 선생님에게 보내고, KLUE 정답은 증류 학습에 쓰지 않는다. 대신 KLUE 정답은 선생님 라벨의 품질을 측정하는 데 쓴다(학습 문장에서 선생님 라벨 대 사람 정답의 P/R/F1).

### 선생님 라벨링 (gpt-5.4-mini)

- 기존 `LLMExtractor`(POLE+O, 이름만 반환)를 쓰지 않고, 이 실험용 라벨러를 따로 만든다.
  - 타입은 3개(person/organization/location)만.
  - 프롬프트에 KLUE 표기 규칙을 **자세히** 글로 설명한다(사용자 결정). 근거는 KLUE 논문 3.4절과 `notebooks/02`의 직함 통계. 최소한 다음을 다룬다.
    - 타입 정의: PS(개인 또는 집단의 이름), LC(행정구역·지리적 위치의 이름), OG(기관·기업의 이름). 근거는 TTA 개체명 지침.
    - 범위 규칙: 조사·어미·문장부호 제외, 이름 뒤의 직함·호칭·직책 제외, 수식어 제외, 원문 표면형 그대로(정규화·번역 금지), 같은 이름이 여러 번 나오면 각각 표시.
    - 타입 결정: 같은 이름이라도 문맥에 따라 판단(예: 매체가 사물로 쓰인 문맥이면 기관으로 보지 않음), 이름이 아닌 일반 명사구는 제외.
    - 날짜·시간·수량은 이번 과제의 대상이 아님을 명시.
  - **few-shot 예시는 넣지 않는다**(사용자 결정). KLUE 문장이나 KLUE 정답이 달린 예시, 특정 실존 사례(예: 특정 인물+직함 조합)를 프롬프트에 직접 넣지 않는다. 규칙은 일반적인 서술로만 전달한다. 직함 제거 같은 KLUE 맞춤 후처리 규칙도 쓰지 않는다.
  - 출력은 엔티티의 원문 표면형(`text`)과 타입. 원문에서 위치를 찾아 `start/end`를 붙이고, 원문에서 찾을 수 없는 엔티티는 버리고 개수를 기록한다.
  - 학습용 변환은 `notebooks/02`와 같은 규칙(모든 레이블을 빈 목록으로 선언, Kiwi 경계와 맞지 않는 범위 제외, 제외 비율 기록)을 따른다.
- 토큰 사용량(입력·출력), 호출 시간, 실패·재시도 횟수를 문장 단위로 기록한다. 비용은 실제 토큰 수 × 실행 시점 단가로 계산하고 단가를 함께 적는다.
- 라벨 결과: `experiments/results/distill_labels.json`.

### 선생님 자체 평가

- 검증 데이터에서는 LLM을 호출하지 않는다(사용자 결정, API 비용 약 70% 절감). 선생님 품질은 학습 2,000문장의 라벨을 사람 정답과 비교한 P/R/F1로 대신하고, 문장당 비용·시간도 라벨링 측정값을 쓴다. 노트북에 이 차이(검증이 아닌 학습 문장 기준)를 명시한다.

## 제약

- 실행 환경: 로컬 macOS CPU (학습 2,000문장 약 4분, 5,000문장 평가 약 4분/조건). GPU는 쓰지 않는다.
- OpenAI 키는 `.env`의 `OPENAI_API_KEY`, 모델은 `LLM_MODEL=gpt-5.4-mini`.
- 커밋은 사용자가 요청할 때만 한다.
- 노트북은 사용자가 다른 환경에서 직접 편집하므로, 기존 노트북을 생성 스크립트로 다시 만들지 않는다.

## 설계자 판단 (리뷰 후 결정, 사용자 확인 대상)

- **호출 설정**: 선생님 호출은 기존 `LLMExtractor`와 같이 Responses API, 추론 강도(reasoning effort) 기본값, 실시간(동기·비동기 동시 호출) 방식으로 한다. 선생님과 기존 LLM 기준선이 같은 설정이어야 비교가 이어지기 때문이다. Batch API(약 절반 단가, 수 시간 지연)는 쓰지 않고, 결론에 대안으로 언급만 한다.
- **로컬 연산 비용**: 로컬 CPU 학습·추론은 금액으로 환산하지 않는다(0원으로 두고 시간만 기록). 손익분기는 "LLM 추론 API 비용이 라벨링 API 비용을 넘어서는 추론 문장 수"로, API 비용과 시간만으로 계산한다. 클라우드 단가 가정은 쓰지 않는다.
- **문장 비용**: 기존 KLUE 원문을 쓰므로 없다. 증류 비용은 라벨링부터로 정의한다.
